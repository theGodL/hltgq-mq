## 结论速览（TL;DR）

1. **新老系统数据同源、月度总量逐站一致**：12 站中 10 站 9 月累计值分角不差（鲤鱼墩 27.5=27.5、白帽 16.5=16.5、周家河 14=14 等）。
2. **"新老展示不一致"由三类原因构成，均不属于 mq 入库问题**：
   - **对比口径错位（主因）**：site 报告使用的"老系统值"实为老系统 9/22 09:45 的实时快照，与"9/21 口径"不可直接对比；
   - **坝上 34.0**：站端灌数（+34）叠加人工修正的边界断差，只存在于新系统链路，老系统根本没有这笔数；
   - **老系统侧归行差异**：鲤鱼墩/白帽在老系统 9/21 未出行、9/22 才补显（数值一致）；马嘶铺老系统多计 0.5。
3. **mq 程序对雨量行只 INSERT、无 UPDATE/DELETE**，坝上 549 行逐条与报文核对 diff 只有"被人工减 34"的两段，入库无责。

## 二、34.0 的完整机制（坝上站 3206400007）

### 2.1 站端灌数（9/18）

9/18 10:20~10:40 坝上报文出现台阶式跳变（报文原文即如此）：

```
17.9 → 19.4(+1.5) → 37.4(+18) → 41.9(+4.5) → 51.9(+10)，累计 +34
```

对应报文：10:20(19.4)、10:35(37.4)、10:36(41.9)、10:40(51.9)，recv 正常（各 +58 秒）。

### 2.2 人工"减 34"修正

- 9/18 11:10 起，库内行值 = 报文值 − 34（如 51.9 → 17.9）；
- 修正覆盖区段：**9/18 11:10 ~ 9/21 10:15 共 154 行，另加 9/21 12:00 行 1 行，共 155 行**，每行 diff 恰好 = −34.0；
- 9/18 10:20~10:48 的 6 条台阶报文在库内没有对应行（被删或被跳过，无日志无法进一步区分）；
- 取证痕迹：
  - 9/21 00:00~09:25 的 25 行 **xmin 连续且逆序**（2630763 → 2630739），为同一批次批量改写特征；
  - 9/21 10:15、12:00 两行 xmin=2639614/2639615（另一批次）；
  - 9/15 起坝上全部 549 行 **updated_at 全部等于 created_at**——被修正的行必然经历过 UPDATE，正常 UPDATE 会刷新 updated_at，说明执行修正的工具把修改痕迹抹平了。

### 2.3 修正断裂与 34.0 的产生

- 9/21 14:10 起新报文（52.4、23:15 起 52.9）**未被修正，原样入库**；
- 修正边界两侧：12:00 行（18.4）↔ 14:10 行（52.4）= **34 断差**；
- mq 的实时统计字段（rainfall1h/3h/6h，取报文值与前值的差）把断差计入：
  - 14:10 行 r3h=r6h=34.5（52.4−17.9）
  - 15:00 行 r3h=34（52.4−18.4）、r6h=34.5
- 页面"9/21 15:00 桶显示 34.0"即该断差，**不是真实降雨**。

### 2.4 全站扫描佐证（result17）

9/17~9/22 全部 **122 站、19059 条报文**，唯一 DYP 大跳变（≥3）只有 3206400007 三处（+18/+4.5/+10），其余 121 站全部正常——**34 只影响坝上一站**。

## 三、mq 入库无责的依据

| 核查项 | 结果 |
|---|---|
| rainInfo 处理链路 | TAG_TABLE_MAP 映射到 `t_auto_hltgq_water_rain_info`，逐条 INSERT |
| UPDATE/DELETE | 全项目无该表数值 UPDATE/DELETE（唯一 UPDATE 是设备迁移字段，不碰数值） |
| computeRainfall | 只计算 rainfall1h / 3h / 6h（窗口取前值差），**不写 rainfall_daily** |
| 去重逻辑 | stcd+tm 已存在则跳过，只新增不覆盖 |
| 逐条对照 | 9/15~9/22 坝上 549 行 vs 报文，diff≠0 仅两段（即 2.2 的 155 行），其余 diff=0 |

结论：库内数据与报文完全一致，差 34 的行是**库外工具**修正所致。

## 四、site 报告待更正点

1. **"老系统对照值"实为老系统 9/22 09:45 的实时快照**（见第五节 5.1），与"9/21 口径"不可直接对比——由此得出的"新老不一致"结论不成立。
2. **"9/21 14:10 报文跳变"表述错误**：14:10 报文正常（52.4），跳变是 12:00 行（18.4）→ 14:10 行（52.4）之间的"人工修正边界断差"。
3. **"数据未被人为修改"不成立**：155 行被减 34、updated_at 被抹平（549 行）、6 条台阶报文行不存在、xmin 批量改写痕迹。
4. **rainfall_daily 全 null 非 mq 职责**：该字段不在 mq 代码写入范围内（mq 只写 1h/3h/6h），不应归咎于 mq 入库，需由负责该字段的服务/工具排查。
5. **"9/21 15:25 批量重写 732 行"已查明（result25/31）**：该 732 行 = **13 个站 2026 年 8 月的历史行**（tm 8/09~8/17），9/21 15:25:06~15:26:02 被某批处理批量刷新 updated_at（多会话并发特征）；xmin 范围 2650710~2651470，与"减 34"修正批次（xmin 2568398 / 2630739~2630763 / 2639614~2639615 / 2645064）**完全不重叠**，与 9/18~9/22 争议数据无关，**非 mq**——疑似运维/平台方的历史数据修复任务，待与操作记录核对；坝上 9/21 15:25 行本身（created 15:25:58）未被重写。
