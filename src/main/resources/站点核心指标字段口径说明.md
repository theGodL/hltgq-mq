## 二、判定依据

### 2.1 平台模型元数据（决定性）

`t_lcode_model_field` 中两个字段的定义原文：

```
field_key = ccnhtm   field_title = 核心指标-水位   base_type = #STRING#   propType = QxString   sort_index = 12
field_key = ijzsby   field_title = 核心指标-雨量   base_type = #STRING#   propType = QxString   sort_index = 13
```

平台声明的是**字符串类型**，而物理表中能承载字符串的只有 `ccnhtm1`/`ijzsby1`（varchar）；全表以 "1" 结尾的列**也只有这两个**——属字段类型变更时新增的列，旧 double 列保留但不再被平台使用。

对照信息（`information_schema.columns`）：

```
ccnhtm   double precision
ccnhtm1  varchar
ijzsby   double precision
ijzsby1  varchar
```

### 2.2 代码写入点（全项目唯一）

`MonitorDataService#updateSiteCoreIndicator` 是按报文类型刷新核心指标的唯一入口，SQL 只拼 `*1` 列：

全项目 grep `SET ccnhtm` / `SET ijzsby`（不带 1）**零命中**。其余触达站点表的语句只有：

### 2.5 为什么 `updated_at` 会误导

站点表 `updated_at` 是**行级**时间戳（timestamp(0)，秒精度），任何列更新都会刷新它：

- `markSiteOnline`：站点当天首条报文到达时写 `zebpsu='#1#' + updated_at`；
- `expireColumn`：核心指标超时置 `'0.00'` 时写 `updated_at`；
- 平台的档案编辑等操作同样会刷新。

所以「10 个纯雨量站的 updated_at 是今天 06:10~06:40」**只能说明今天有报文到达，不能说明 27.3 是今天写的**。这些站的 river_info 自 2026-10-27 清理后已无任何数据（近 24h 入库 0 条），而写 `ccnhtm`/`ccnhtm1` 的唯一入口是「riverInfo 入库成功后」——物理上不可能产生新值。

## 三、写入与失效机制（`*1` 列）

### 3.1 实时刷新

| 触发 | 条件 | 写入 |
|---|---|---|
| riverInfo 入库成功 | Z 有效（非哨兵、>0） | `ccnhtm1 = 修正后海拔`（format2 两位小数） |
| rainInfo 入库成功 | 当前降雨量可算（DYP>0、基线有效、跳变未超限） | `ijzsby1 = DYP 增量`（两位小数） |

- 无效值/哨兵值/跳变**不覆盖**，保留上次有效值；
- 双要素站两列各写各的互不占用；
- 被档案守卫拦截的报文不入库、不刷新核心指标（水库 13 站的纯雨量站 riverInfo 属此类）。

### 3.2 时效巡检归零（每 5 分钟）

`expireStaleCoreIndicators`：按 `stcd|tag` 学习实测上报周期，距最近心跳超过 `max(实测周期, 下限) + 5 分钟` 时，对应列置 `'0.00'`（带乐观锁，不覆盖窗口内新写入的值）。

- 水位下限 2h、雨量下限 1h；
- 从未收到过报文的列（NULL/历史 `'--'`）也统一置 `'0.00'`。

### 3.3 离线归零（每小时 :05）

`checkOfflineSites`：站点 24h 全类型报文均无数据 → `zebpsu='#2#'`，同时 `ccnhtm1='0.00'`、`ijzsby1='0.00'`。

### 3.4 重要语义

`'0.00'` 表示**当前无新数据**（超时/断连/从未上报），不是故障，也不是"没有该监测项"；设备恢复上报后由下一条报文自动写回真实值。

雨量口径是**当前降雨量**（最新 DYP − 当日 08:00 基线 DYP），不是日累计、不是历史降雨。

## 五、site 侧读取约定

### 5.1 字段映射

| 对外接口语义 | 应读列 |
|---|---|
| type=1 水位 / coreIndicator 水位 | **`ccnhtm1`** |
| type=2 雨量 / coreIndicator 雨量 | **`ijzsby1`** |

### 5.2 值语义

- 有值且非 `0.00`：该站当前实时值（两位小数字符串）；
- `'0.00'`：当前无新数据（超时/断连/从未上报），**按 0 展示即可，不要视为故障**；
- NULL：从未写入（极少，通常被时效巡检补成 `'0.00'`）；
- 历史 `'--'`：旧版失效标记，已废弃，遇到按 `'0.00'` 处理。

### 5.3 禁止事项

1. **不要读 `ccnhtm`/`ijzsby`（double）**：值永久停在 2026-09，会得到"雨量恒 0、水位恒定"的假象；
2. **不要用站点表 `updated_at` 判断核心指标新鲜度**：行级时间戳，在线标记等操作都会刷新；
3. **不要把 `ijzsby1` 当作日累计雨量**：它是「最新 DYP − 当日 08:00 基线」的当前值；需要日累计/时段雨量请走 `/station-metrics` 等自算接口。

### 5.4 如果业务坚持读 double 列

mq 侧可以恢复 v4 的双写（同一条 UPDATE 同时写 `ccnhtm1`+`ccnhtm`、`ijzsby1`+`ijzsby`，两列同源不漂移），但需先确认：

- 接受 double 列现有历史值（旧水位/档案参考值）被实时值覆盖；
- double 列与 `*1` 列的清洗口径保持一致（假值清理需覆盖两列）。

未确认前维持现状：**只写 `*1` 列**。

## 七、常见误判（FAQ）

| 疑问 | 回答 |
|---|---|
| 纯雨量站 ccnhtm=27.3，是今天写的吗？ | 不是。27.3 是 2026-09 前旧版写入的假水位；今天刷新的是行级 updated_at（报文到达标记），与 ccnhtm 无关。 |
| 雨量列全是 0.00，是不是没入库？ | 不一定。先看 rain_info 是否有数据、当天 DYP 是否有增量；无降雨时当前降雨量真实值就是 0。2026-11-02 核对时 12 个水库站 DYP 全天无变化，0.00 为真实值。 |
| 平台页面显示的值和 site 接口不一致？ | 平台页面读 `*1`（STRING 字段），site 若读 double 列就会不一致。统一读 `*1`。 |
| 为什么 `ccnhtm1` 有时是 0.00 而 river_info 有数据？ | 报文超过实测周期+5 分钟未更新、或站点 24h 断连，时效/离线条线会置 `'0.00'`；下一条报文到达自动恢复。 |
| 闸站为什么没有核心指标水位？ | 闸站水位（Z1/Z2）走 gate 表 up_z/down_z，不写核心指标列（既定口径）。 |
| 双要素站（如坝上 #1#\|#2#）两列会互相覆盖吗？ | 不会。按报文类型分列写入，各写各的。 |
