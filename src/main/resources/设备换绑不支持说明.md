# 设备换绑对遥测设备不支持的说明（致展示层）

> 出具方：hltgq-mq　日期：2026-09-28　**紧急程度：高**
> 目的：站点-设备管理中的"换绑"操作对**遥测设备**（产生报文的设备）不适用。请在业主使用该功能前尽快完成展示层修改（禁用/隐藏相应入口或强警示），避免业主操作后产生"台账与数据不一致"的数据口径异常。

> **落实回执（hltgq-site，展示层）**：已于 2026-09-28 完成本说明要求的全部改造并通过自检——遥测设备候选禁选 + 接口 400 双重拦截，判据采用设备表 type 字段（仅纯视频 `#5#` 可换绑）；历史冲突式校验与相关接口字段已同步清理。详见文末"六、展示层落实回执"。

---

## 一、结论

**对 mq 自动创建的遥测设备（每站一台，如"花凉亭坝上水位计#"），换绑对数据归属零作用，且会造成台账 / 数据 / 统计三方不一致——请展示层禁用（或隐藏）此类设备的换绑入口；换绑仅保留给不产生遥测数据的设备档案（如视频设备）。**

---

## 二、事实依据（mq 源码级核验 + 数据库只读实查，2026-09-28）

### 1. 报文里没有设备标识，归属识别只有站号

雨量报文原文（实查）：

```json
{"tag":"rainInfo","entity":{"STCD":"3206400007","TM":"2026-09-28T16:00:00","DRP":0.0,"PN05":0.0,"INTV":null,"PDR":null,"DYP":56.4,"WTH":null},"ctime":"9/28/2026 4:00:58 PM"}
```

仅有 STCD（站号），无任何设备编号——mq 只能按站号识别数据流。

### 2. 新入库数据的 stcd / site / device 三列解析链（与设备台账无关）

- `stcd` ← 报文自带（站号）；
- `site` ← `lookupSite(stcd)`：按站号查**站点表**（iofhpi 字段）映射；
- `device` ← 按"站名 → 设备名（站名+类型#）"查设备表（`lookupOrCreateDeviceByName`）——**查到即复用其 id，从不读取该设备行的 site 列**；mq 重启后按名重建缓存，仍得同一 id。

**换绑（`UPDATE device SET site = 新站`）修改的 `device.site` 列，不在这条链任何一步的输入中。**

### 3. 实查佐证（只读）

rain_info 全表 21 个雨量站，`stcd ↔ site ↔ device` 严格 1:1、无任何切换历史。
（例：坝上站 3206400007 ↔ site heLqnpaEBfGyLQauYcA ↔ 设备"花凉亭坝上水位计#" sY8rwpxtydfwxAnsFhBa）

---

## 三、换绑后的实际行为与后果

**数据落库无异常**：换绑后新入库数据的 `stcd / site / device` 三列全部保持**原先的值**（不变）。

**异常发生在读取设备台账（device.site）的环节**：

| 环节 | 换绑后的行为 | 后果 |
|---|---|---|
| 失联告警挂靠（mq `checkOfflineSites`：按 `device.site = 站点id` 选设备） | 设备从原站名下消失、归入新站名下 | 原站失联告警挂靠错乱/缺失；新站可能出现不属于其数据的设备判定 |
| 到报统计站点全集（mq `ArrivalStatsService`：按 `device.site` 判定"有设备的站"，评估已源码级核验） | 原站/新站"设备集合"变化 | 到报率/联通率统计口径偏移 |
| 展示页面 / 台账 | 设备显示归属新站，其数据仍落在原站 | "设备在 B 站、数据在 A 站"，误导业主与管理人员 |

### 验证方法（联调可复现）

> 写操作需在生产窗口由有权限方执行，验证后恢复原值。

1. 对任一台雨量站遥测设备执行换绑（改其 site 到另一站）；
2. 等该站下一份报文入库 → 查最新数据行：`stcd / site / device` 三列均为换绑**前**值；
3. 查 device 台账行：`site` 已为换绑**后**值；
4. 观察失联告警挂靠与到报统计的偏移；
5. 恢复原 site。

## 四、修改要求（展示层）

1. **对 mq 自动创建的遥测设备，禁用或隐藏换绑入口**（或至少禁用提交并强警示）。
   - 识别特征（建议）：设备名**以站名开头、以 "#" 结尾**（如"花凉亭坝上水位计#"、"XX站1#"）；此类设备由遥测系统自动创建（`device.created_by = 'SYSTEM'`）——展示层可结合实际实现选择识别方式；
   - **实测修正（2026-09-28，site 落实反馈）**：视频设备同为 `created_by='SYSTEM'`、全库设备名普遍以 "#" 结尾——**名称与创建者两种特征均会误伤**；实际落实判据改用设备表 `type` 字段（仅纯视频 `#5#` 可换绑，其余一律禁绑），详见回执第 2 条；
2. **换绑功能仅对人工维护的设备档案开放**（如视频设备等不产生遥测数据的设备）；
3. **同类复核**：此类遥测设备的**改名、删除入口**同样不得开放（此前已约定不改名、不删除——改名/删除会触发 mq 自动重建设备，导致同一站数据按 device 分裂）；请一并检查实现；
4. 若产品确实需要"设备挪站"，唯一生效方式：**设备端修改站号（RTU 配置）** → 报文自动进入新站（mq 自动建链）→ 台账随之登记。**平台换绑不是、也不可能是数据迁移手段。**

## 六、展示层落实回执（hltgq-site，2026-09-28）

> hltgq-site（站点详情「设备信息」换绑入口）已完成本说明要求的全部改造，并同步清理历史逻辑。以下供 mq 侧闭环归档。

**对应"四、修改要求"逐条落实：**

1. **遥测设备禁用换绑——已落实（候选 + 接口双重拦截）**：
   - 候选列表（`GET /station-detail/device/bindable`）：遥测设备一律返回 `blocked=true`，界面置灰禁选并展示原因；
   - 换绑接口（`POST /station-detail/device/bind`）：同规则服务端最终拦截，一律 400「该设备为遥测设备，不支持换绑；如需调整归属，请修改设备端的站点编码配置」。
2. **仅不产生遥测数据的设备可换绑——已落实；判据取设备表 `type` 字段，未采用名称/创建者特征**：
   - 实际判据：仅**纯视频设备**（`type` 按 `|` 拆分后全部为 `#5#`）可换绑；水位/雨量/流量/闸孔/墒情/水质及 type 为 NULL 的待接入设备全部禁绑；
   - 原因说明（供 mq 知悉）：实测核验发现——视频设备同为 `created_by = 'SYSTEM'`、且全库设备名普遍以 `#` 结尾（含视频），故"名称特征"与"创建者"两种识别方式均会误伤；`type` 字段是唯一能精确区分"是否产生遥测数据"的权威判据（即本说明第四节第 1 条"结合实际实现选择识别方式"之选择）。
3. **改名 / 删除入口复核——已核验：站点详情页本就无设备改名、删除入口**，无需改动。
4. **"设备挪站唯一生效路径 = 修改设备端站号配置"——已采纳**：作为提示文案直接落于界面（"如需调整归属，请修改设备端的站点编码配置"）。
